#### A. What is it
(+) Create a nd manage APIs, which is the endpoint or entry point for applications.
(+) It sits between application and integration (services)
(+) Highly available, scalable, handles authorization, throttling, caching, CORS, transformations, OpenAPI spec, direct integration and much more.
(+) It is a public service which can connect to services/endpoints in AWS or onpremise.
(+) It supports HTTP APIs, REST APIs, and WebSocket APIs

#### B. Authentication
(+) APIGW can either use `AWS Cognito` or `Custome Authentication` for authenticating request
(+) For `AWS Cognito`, the request include a token, which APIGW will send to Cognito to verify and allow the request in or not.
(+) For `Custom authentication`, we will need to create a `Lambda Authorizer`, request will include a token, which APIGW will pass to `Lambda Authorizer` and it will return an IAM policy with principal identifier. APIGW will then handles the request or return `403 Access_denied` to the client.

#### C. Endpoint Types
(+) `Edge-Optimized` which will route to the nearest CloudFront POP
(+) `Regional` which will route to the clients in the same region
(+) `Private` which will route to interface endpoint within a VPC

#### D. Stages
(+) APIs are deployed to stages, each stage has one deployment.
(+) Where in APIGW, each stage has its own endpoint and its own backend.

![[Pasted image 20260402165557.png]]

#### E. Errors
(+) `4xx` - `Client Error` - Invalid request on `client` side
==> `400`: Generic Bad Request
==> `403`: Access denied, authorizer denies
==> `429`: exceed a throttling amount
(+) `5xx` - `Server Error` - Valid request, `backend issue`
==> `502`: Bad gateway exception - bad output returned by Lambda
==> `503`: Service unavailable - backing endpoint is offline, major service issues
==> `504`: Integration failure/timeoune - 29s limit

#### F. Caching
(+) Caching is defined per stage within APIGW.
(+) Cache TTL default is 300 seconds, and can be configurable min `0` and max `3600s`. It can be encrypted and the size is `500MB` to `237GB`. This will reduce load and cost and overall improve performance
(+) Calls to the integraation are only made if a request is a `cache miss`
