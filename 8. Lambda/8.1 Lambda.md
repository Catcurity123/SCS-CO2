#### A. What is it
(+) Function-as-a-Service (FaaS), which we give it a piece of code, it will runs and return the result.
(+) Function use a runtime (e.g. Python 3.8), the code is loaded and run in a runtime environemnt.
(+) The environment has a direct memory allocation. Which we are billed for the duration that a function runs.
(+) The deployment package is `50 MB zipped and 250 MB unzipped`
(+) We directly control the memory allocated for Lambda function raging from` 128MB -> 1024MB of memory`, we also allocated `512MB storage and up to 10240MB`
(+) The Lambda function will only work for `900s or 15mins`, after that it will be timeouted, we can use step function to bypass this.

#### B. Lambda Security and Monitoring
(+) Lambda can be either `Public Lambda` or `Private Lambda`

###### Public Lambda
(+) `Default` configuration for Lambda Function, in this state it is automatically given public networking, meaning it can access `public AWS services` and the `public internet`.
(+) This mode offers the best performance as it does not require VPC's configuration.
(+) In this mode, Lambda` will NOT have access to VPC-based services`, unless the service has public IPs and security group has allowed external access (anti-pattern)

![[Pasted image 20260317190600.png]]

###### Private Lambda
(+) In this mode, Lambda function running in a VPC `obey all VPC networking rules.`
(+) NatGW and IGW are required for VPC Lambda to access internet resources.
(+) Now, Lambda Function in the same subnet with the same security group use only one ENI, prior to each Lambda function require unique ENI in the pass.
![[Pasted image 20260317191140.png]]

###### Lambda Security
(+) What a Lambda can do relies on `Lambda Execution Role`, which is attached to Lambda function, this controls what the function can do.

(+) What can trigger a Lambda relies on `Lambda Resource Policy`. which controls what services and account can invoke lambda function. Currently, Lambda's Resource Policy can only be changed using CLI or API.

###### Lambda Logging
(+) Lambda uses `CloudWatch, CloudWatch Logs & X-Ray`
(+) Logs from Lambda's execution will go to `CloudWatch Logs`
(+) Metrics about invocation success/failure, retries, latency will go to `CloudWatch`
(+) Lambda can be integrated with X-Ray for `distributed tracing`, where we want to understand which path it goes.
==> `CloudWatch Logs` if used by Lambda will require permission via Execution Role


#### C. Lambda's Invocation methods
(+) To trigger Lambda, there are `Synchronous, Asynchronous and event source mapping`

###### Synchronous Invocation
(+) CLI/API invoke a lambda function, passing in data and `wait for response`.
(+) Result is returned during the request, and error or retries have to be handled within the client
![[Pasted image 20260317192136.png]]

###### Asynchronous Invocation
(+) Typically used when AWS service invoke Lambda function
(+) Lambda is responsible for retrying error or retries.
(+) Lambda function need to be idempotent (lab)
(+) Events can be sent to a DLQ after repeated failed processing.
![[Pasted image 20260317192528.png]]

###### Event-source mapping
(+) Typically used on streams or queues which dont support event generation to invoke lambda (Kinesis, DynamoDB stream, SQS)
![[Pasted image 20260317192756.png]]

#### D. Lambda Version & Execution context
(+) Lambda functions have version - v1, v2, v3. A version is the code + the configuration of lambda function
(+) It is immutable - it never changes once published and has its own ARN
(+) `$Latest` will point at the latest version. We can also create Aliases (Dev, Stage, Prod) point at a version.

###### Execution Context
(+) An execution context is the environment a lambda function run in.
(+) `A cold start` is a full `~100ms` creation and configuration including function code downlaod
(+) `A warm start` is the same execution context being reused. A new event is passed in but the execution context creation can be skipped.
==> `Provisioned concurrency` can be used. AWS will create and keep X contexts warm and ready to use, improving start speeds.
