###### A3. What are the risks of using L345 only
(+) A network relying solely on an L3/4/5 firewall is blind to the content of the traffic it permits. These firewalls, often called packet-filtering or stateful firewalls, make decisions based on source/destination IP a![[Pasted image 20250614203645.png]]ddresses (Layer 3), TCP/UDP ports (Layer 4), and session state (Layer 5). 
==> It is blind to threat posses by legitimate connection. For example:
	(-) A traditional network allows for outbound connection on port 443 (which is normal for inside users to browse the internet) but there is a malware inside the company. When the firewall inspect the outgoing packets, it sees the legitimate port and allowed for exfiltration of data.
	(-) A traditional network allows for inbound connection of a range of public IP (143.53.42.1/24 for example), but the malicious entities in that IP ranges perform SQL Injection attack on the company website.

==> The L3/4/5 firewall was completely ineffective because it lacked the `capability to perform deep packet inspection (DPI)` to look inside the encrypted payload and identify the malicious activity. 
==> The risks include L7 vulnerabilities such as SQL Injection, XSS, Application-layer DDOS. 

###### A4. What are the risks of using L7 only
(+) Using only an L7 firewall, such as a Web Application Firewall (WAF) or a full Next-Generation Firewall (NGFW), without the support of L3/4/5 filtering, exposes the network to performance degradation and foundational network-layer attacks. 
==> L7 inspection is resource-intensive, and forcing it to process all traffic, including malicious floods, can overwhelm it, for example:
	(-) The attacker uses a botnet to launch a **SYN flood attack**. This involves sending a massive volume of TCP SYN packets (the first step in the three-way handshake) to the company's web servers, The L7 firewall becomes overwhelmed and exhausted. It can no longer process new connection requests from legitimate users, resulting in a Denial of Service (DoS).
	(-) The attackers running a sport scan against company's entire public IP range, the L7 firewall sees a storm of connection across a vast range of ports (22, 3389, 1433), since the L7 firewall's job is to inspect application data, it wastefully allocate resources to process these probes. Resulting them to ignore or pass the request, or process it and waste all the resources
	(-) An employee's laptop is compromised with malware. The attacker is now "inside" the corporate user VLAN. Their goal is to reach the critical database servers, which reside in a separate, high-security server VLAN. The attacker found out that 3389 port is open, and inside the remote desktop, the attacker can connect to database using SMB protocol 445.

==> The risks include L3/4/5 exploits such as Volumetric DDoS Floods, IP Spoofing, Reconnaissance Scans, Lateral movement/exploit using non-web protocols


#### B. VPC Firewalls
(+) In traditional Data Centers and in Public Cloud, Firewalls are security measures designed to segment a network into different security zones, separating sensitive data and critical infrastructure from less trusted parts of the network.

==> This isolation helps` contain security breaches and limit potential damage`. They act as the first line of defense,` controlling inbound and outbound traffic based on predefined rules and policies`

###### B1. Security Groups
(+) EC2 has one or more virtual network interface card (vNIC) attached to it, and data sent from and to EC2 will go through this vNIC, and `SG` is assigned to AWS resource, specifically the network interface.
(+) `SG` is `stateful`, meaning that `SG` remember the characteristic of the incoming connection, and when the outcoming connection matches it, it will automatically allows the outbound connection. This will mean that only one rule is needed for conenction, in the contrary to `NACL`. 

###### NOTE: 
(+) It remembers by using a tracking function in the hypervisor, this tracking records the information about the connection (including the port information) so that when the response went back, it is allowed. (https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/security-group-connection-tracking.html)

(+) `SG` understands AWS's resources, therefore, not relying entirely on IPs or Networks. Meaning that we can refer AWS resources instead of its IPs.
(+) `SG` has an `hidden implicit deny` meaning that rules that are not `explicitly allows` will be understood as `denied` and 1 `SG` does not have `explicit deny`.
(+) `SG` is attached to ENI's not instances

###### B2. Network Access Control Lists (NACLs)
(+) `NACL` can be though of as the `firewall` that surronds `Subnets` in a VPC, therefore, connection from resources in a subnet travelling to another subnet will go through NACL, but resources within a subnet when communicating will not go through NACL.
![[Pasted image 20240108113641.png]]

(+) By default, NACL is designed to allows everything both inbound and outbound.
(+) When a client making a connection to an instance with NACL applied, let's say client is making HTTPS request, meaning using `TCP/443`. From the instance's perspective, the inbound rule is TCP/443, but when the instance want to respond to the client, it will choose a random `ephemeral port` to transmit the data. Therefore, we need to implement a rule for this transmission.
![[Pasted image 20240108114344.png]]

(+) Things will get even more complicated if the web server is just an interface an it will need to connect with the application in another subnet, if that's the case, we will need to implement outbound and inbound rule for this connection in both the web's NACL and the app's NACL.
==> Therefore, to ease things up, NACL is by default allows everything on both ends.

`Note`
(+) When Bob is making a request, he is conducting the `Initiation` process, and when the web instance's connect with Bob it is conducting the `Response` process, these processes are 2 different streams of connection with 2 different rules. The instance makes no sense of the 2 streams and need to applied 2 different NACLs to them ==> Therefore, NACL is `stateless`, meaning it can not make sense of the connection stream.
(+) NACL only impacts data `crossing subnet border`, meaning it will only affects data coming from and to instance on different subnet.
(+) NACL can `explicitly allow and deny`.
(+) IPs/Networks, Port and Protocols are supported, not logical resources.
(+) NACLs cannot be assigned to AWS resources, only subnets.
(+) Use with SG's to add explicit Deny (Bad IPs/Nets)
(+) One subnet can only be assigned with one NACL at a time.
(+) Process in order from the lowest to the alterisk, ==> NACL is `order processing`.

###### B3. Web Application Firewall (WAF)
(+) Amazon's take on L7 application firewall, the main configuration unit is `Web Access Control Lists (WEBACL)`
(+) `WEBACL` Default Action (Allow or Block) - Non matching, basically black listing or white listing.
(+) `WEBACL` can be configure for `Global` (CloudFront) or `Regional` services (ALB, APIGW, AppSync). For Regional services, we need to specify the region upon which we want to deploy the service and WAF.
(+) We need to add `Rule Groups` or Rule for WAF to work, and this will be proceeded in order.
(+) Rules have a specific compute limit called `Web ACL Capacity Unit (WCU)` - default is `1500` unit. This is the indication of the complexity of rules.
(+) WebACL are associated with resources.

(+) Rule Groups contain rules, dont have default action, that's defined when groups or rules are added to WebACL
(+) Groups can be either managed (AWS or marketplace), or yours, service-owned.
(+) Rule Groups can be referenced  by multiple WebACL.

(+) Rules contain `Type`, `Statement - one or more think of condition`, `Action - what to do if condition matched`.
(+) `Type` can be either `Regular - what happen or not`, or `Rate-based - the volume of which the action happen`.
(+) `Statement` can be `What to match`, `Count all` or `What & Count`. It can contains: Origin country, IP, Label, Header, Cookies, Query Parameter, URI path, query sring, body, HTTP method. This can be configured with `AND, OR, NOT, or SINGLE`
(+) `Action`: Allow, Block, Count, Captcha or custom response

###### B4. R53 Resolver DNS Firewall
(+) R53 Resolver DNS Firewall provides advanced protection against DNS-based threat and malicious activity. It is designed to enhance the security and reliability of DNS infrastructure by` filtering and blocking potentially harmful DNS queries and responses`.

(+) This service integrates with AWS Route 53 Resolver, which is a DNS resolution service that makes it easier to connect and route traffic between on-premises networks and AWS resources.

==> Unlike SGs and NACLs which filter traffic based on post/protocol and IP address, DNS firewalls can filter traffic for specific domain names e.g. blocking access to a known phishing website.

###### B5. AWS Network Firewall
Till now the firewalls that we have discussed fall into 2 categories –

1. Those that work at a resource-level – SGs (instances/databases), WAF (Web application resources like CloudFront, ALB, etc.), DNS Firewall (Route 53)
2. Those that work at a subnet-level – NACLs 

But none of them is able to filter traffic at the perimeter of the VPC

AWS Network Firewall does exactly that i.e. it is stateful, managed, network firewall and intrusion detection and prevention service for the perimeter of VPC. This includes filtering traffic going to and coming from an internet gateway, NAT gateway, or over VPN or AWS Direct Connect. Network Firewall uses the open source intrusion prevention system (IPS), Suricata, for stateful inspection.

#### C. Logging and Monitoring VPC's flow

###### C2. Is VPC Flow Logs the only network log in AWS
(+) No, there are many more depending on the type of AWS services you may be using. If you are using Load balancers in front of your application, then AWS provides Access Logs that capture detailed information about requests sent to the load balancer.
(+) For AWS web services that might be offering web content directly to users e.g. AWS CloudFront and AWS S3, there are also Access Logs which contain detailed information about every user request that the service receives.

###### C3. What are the fields that can show up in a VPC Flow Log.
- Fields to identify the source of the request
    - srcaddr
    - srcport
    - pkt-src-aws-service
    - pkt-srcaddr
- Fields to identity the destination of request
    - dstaddr
    - dstport
    - pkt-dst-aws-service
    - pkt-dstaddr
- Fields with metadata about the AWS resource for which the flow is captured
    - vpc-id
    - subnet-id
    - account-id
    - instance-id
    - interface-id
    - region
    - az-id
    - sublocation-type
    - sublocation-id
- Fields to describe the traffic and the packet within it
    - bytes
    - packets
    - flow-direction
    - traffic-path
    - protocol
    - tcp-flags
    - type
- Fields with metadata about the context of request
    - start
    - end
    - action
    - log-status
    - version
