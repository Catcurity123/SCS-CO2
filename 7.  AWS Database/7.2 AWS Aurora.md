#### A. Aurora Key Differences
(+) Aurora Architecture is very different from RDS, it uses a Cluster
(+) It is a single primary instance + 0 or more replicas.
(+) It does not use local storage but use cluster volume
==> Meaning faster provisioning and improved availability and performance.

#### B. Aurora Storage Architecture
(+) All SSD based - `high IOPS, low latency`
(+) Storage is billed based on `what's used` - no need to allocate initially.
(+) `High water mark` - billed for the most used, storage which is freed up can be re-used
(+) Connect to Aurora is through `Cluster endpoint` and `Reader endpoint`. `Cluster endpoint` only points at the Primary cluster the `reader endpoint` will be load balanced between other RRs

#### C. Aurora costs
(+) No free tier
(+) Compute - hourly charge, per second, 10 minutes minimum
(+) Storage - GB-month consumed, IO cost per request.
(+) 100% DB Size in backups are included
(+) Backups in Aurora work in the same way as RDS, but restore will create a `new cluster`
(+) `Premium feature` include backtrack which can be used to allow `in-place rewinds` to a previous Point in Time.
(+) `Premium feature` include fast clones which make a new DB much faster than copying all the data.
